# Live Counter for OBS: Improvement Review (2026-09-25)

**Verdict.** The project is in good shape. Typecheck is clean, the build works, all 473 unit tests pass, and the review found no correctness defects in the counting engine or the on-air renderer. There is little to gain from size or runtime tuning. OBS loads the pages from local disk about once per launch, and most byte savings would either remove a documented feature (imported presets can use any font weight) or make no difference anyone would notice. The real upside is in three places. First, the dock's safety net during a live service: two confirmations can end or wipe a count with no way back, the LIVE indicator does not stand out, and the safety prompt can appear off-screen. Second, the first install: the shipped README points at paths that are not in the zip, and nothing says hotkeys need the OBS connection. Third, two overlay issues the audience can see. Almost all of these are small changes.

**1. End-session confirm has no Cancel.** `renderEndConfirm()` adds only "End, keep overlay" and "End, hide overlay" (src/dock/views/live.ts:1182-1199). Clicking End sets `endConfirmOpen = true` (live.ts:1102). Clicking End again does not toggle it off, and only the two end handlers clear it (live.ts:1187, 1192). Switching tabs does not clear it either (src/dock/main.ts:135-143). The Reset confirm right next to it does have a Cancel (live.ts:1169-1176). Counting still works while the box is open, but a non-technical operator sees two armed End buttons and may think they must pick one. Recommendation: add an `end-cancel` button copying `reset-no`, plus one spec.

**2. Setup "Start session" silently replaces a running session.** `onStartSession()` checks only form validity (src/dock/views/setup.ts:1191-1231, 728-730). `startSession` then creates a new session at the start value with an empty undo stack (src/dock/controller.ts:404-411, src/engine/counter.ts:33,40), so Undo cannot bring the old count back. Start sits beside "Update session" (setup.ts:2124-2142), and the operator asked to use Update during services (PRD.md:170). Presets already guards this case (src/dock/views/presets.ts:236-246). Leaving Setup out was a scope decision, not a design one (phase 2 ledger:29). Recommendation: when a session is active, show an inline confirm, "Replace the running session? The current count (N) will be lost", with Replace and Cancel buttons and a pointer to Update session. Change the spec at tests/ui/presets-setup.spec.ts:3349 to expect the prompt.

**3. Release zip and README disagree; packaging is by hand (INSTALL-1, DEVFLOW-2, SIZE-5).** README.md:23 says to copy the `live-counter` folder, :25 says "Double-click `dist/setup.html`", and :38 says "from the project folder". The zip unpacks to a flat `live-counter-for-obs/` folder with no `dist/`, and the README inside it is identical to the repo copy. The bundled TESTING-CHECKLIST.md is docs/phase3-obs-checklist.md renamed, and it also refers to `dist/` and `npm run build`. release/ is git-ignored (.gitignore:9) and no packaging script exists (package.json scripts; scripts/ holds only two copy scripts). The `dist/setup.html` wording is locked by tests/protocol/readme.test.ts:45, the phase 3 plan (:206) and PRD.md:81, :314. Recommendation: add `scripts/package-release.mjs` and an npm script that cleans dist/, builds, copies an explicit allowlist and zips the result, named with the package.json version. Then pick one layout. Either (a) keep a `dist/` subfolder inside the release folder, so the locked README stays true (the smaller change), or (b) reword the README for the flat layout and amend the test, plan and PRD together. Leave the gate checklist out of the final operator zip (roadmap 4.5). No stale release exists today.

**4. Hotkeys need the OBS connection, and nothing says so (OBSINT-3, INSTALL-2).** A hotkey press goes from the Lua script to the channel input's settings, then through obs-websocket's InputSettingsChanged event to the dock (src/lua/counter-hotkeys.lua:141-144, src/dock/hotkey-bridge.ts:49-51, src/shared/bridge-contract.ts:9-12). Yet the "Not now" note on the Connect card (live.ts:760) and the Transport help text (src/dock/diagnostics.ts:113-114) list what connecting adds without mentioning hotkeys. The Hotkeys row ignores connection state (diagnostics.ts:904-909), so an operator with no connection is told to "add counter-hotkeys.lua" (diagnostics.ts:122-123) even when the script is already installed. Recommendation: add "keyboard shortcuts and Stream Deck" to both strings. Pass the client state to `hotkeysRowState` and show "Keyboard shortcuts need the OBS connection above" when the dock is not connected. Add one README sentence under Hotkeys (README.md:34-53). Keep the password as a normal setup step (PRD.md:82-84), and do not suggest turning off authentication, which PRD.md:277 requires. Whether the "Not connected" banner should stay quiet after "Not now" (main.ts:487-495) is a judgment call to settle at the walkthrough.

**5. LIVE and SHOWING (PREVIEW) chip states have no styling.** Only the `showing`, `hidden` and `unknown` states are styled (src/dock/dock.html:228-242), but there are five states (src/dock/live-status.ts:46). The base chip rule has no background (dock.html:219-227), so LIVE renders as plain bold text while HIDDEN gets a red pill. In the usual Studio Mode flow (checklist D1, docs/phase3-obs-checklist.md:36), the two states the operator actually sees are the unstyled ones. PRD.md:221 calls the chip "the continuous safeguard". Recommendation: add CSS rules for `live` (strong, and clearly different from HIDDEN) and for `showing-preview`, plus a spec that checks all five states have a background. A tooltip for LIVE (whose detail is null, live-status.ts:85) is optional. SHOWING (PREVIEW) already has one.

**6. Live-safety confirm can appear off-screen.** The safety box is added last, below Reset and End (live.ts:1020), and it never takes focus or scrolls into view (live.ts:1205-1233). In a dock around 250-300 px tall, clicking Show on a live scene looks like it did nothing. Recommendation: call `scrollIntoView({block:'nearest'})` and focus Cancel when the box opens, or render the box next to the control that triggered it. Do not disable +1/-1 or add a backdrop: PRD.md:221 guards only Show, Reset and Jump.

**7. Overlay stays blank up to 2 s after it reloads.** The overlay says "hello" when it starts (src/overlay/main.ts:174, 205-207). The dock sends state only after a command or on its 2 s heartbeat (controller.ts:86, 691-703), and every dock listener treats "hello" as a liveness ping only (live-status.ts:187-199, live.ts:1309-1312, diagnostics.ts:1487-1488). The renderer draws nothing until the first state arrives (src/overlay/renderer.ts:218, 379). This happens on a manual Refresh, and on Diagnostics' Fix, which says it will "reload it on air" (diagnostics.ts:723). Recommendation: add a public `rebroadcast()` to the controller and call it only on `kind === 'hello'` (not on the periodic `overlay-status`), debounced to about 250 ms. This is safe because the renderer animates only when the value changes.

**8. Clicks may be lost during an automatic count (RUNTIME-2).** Every controller update, including each automatic tick, rebuilds the whole Live pane (`innerHTML = ''` at live.ts:439, via live.ts:1308). If a press starts before a tick and ends after it, the button under the pointer is replaced and the click never fires. That is an estimated 10% chance at the default 1 s interval and 40% at 0.25 s, and it affects Pause, Faster, Slower, Reverse, Show/Hide and Undo. Not reproduced yet: Playwright clicks have no hold time. Recommendation: first add a spec that uses `click({ delay: 150 })` on Pause at the 0.25 s speed. If that fails, add a tick-only fast path that updates the current value, the progress line, Undo's disabled state and the +1/-1 disabled flags (live.ts:1032, 1036) in place, and keep the full render for status, mode, visibility and session changes. The full rebuild is documented design (live.ts:7-18), so keep this a narrow exception.

## Worth doing later

### Size
No separate size item survived review. The only size-related change worth making is the packaging script (item 3). The font and CSS savings that were examined are listed under "Considered and rejected".

### Runtime
- **Mirror write on every tick (RUNTIME-1).** Every accepted command, ticks included, sends a SetPersistentData request right away (controller.ts:527-529, src/protocol/persistence.ts:398-401, 311-319). At the default speed that is one small request per second, which the stream will not notice. If you ever change it, skip the mirror only for automatic ticks and keep it for operator commands and status changes. It must not race the end-session tombstone or Reset (persistence.ts:398-410, main.ts onResetAll). Do it after the walkthrough.
- **Overlay subscribes to events it ignores (RUNTIME-7).** The overlay uses mask 9 with the comment "same subscription set the dock uses" (src/overlay/main.ts:7-11), but the dock uses 394249 (src/dock/main.ts:39-41), and the overlay only reads CustomEvent (src/protocol/bus.ts:103-110). This only matters for overlays opened with `?port` or `?pw`. Fix the comment and set the mask to General the next time the file is touched.

### Install flow
- **Password instructions describe the wrong screen (INSTALL-3).** README.md:26 never mentions OBS's Show Connect Info button. README.md:28 and src/setup/setup.html:164 send the operator to Diagnostics and Save, but the dock opens on Live with a focused Connect card (main.ts:146, live.ts:475-481), which is what PRD.md:84 describes. Reword both files in the same pass as item 3.
- **Moving or renaming the folder (INSTALL-5).** README.md:71-75 covers only moving to another computer and never says to re-add the Lua script, while README.md:23 invites relocation. It already happened once (docs/install-guide/img/obs-dock-file-not-found.png shows the pre-20780a6 path). Add a README paragraph now: re-add the dock, click Fix overlay settings, and re-add counter-hotkeys.lua. Later, add a stale-path check to the overlay scan (diagnostics.ts:476-477, 270-284) and mention the address in Fix's confirm text (diagnostics.ts:721-724); medium effort, since 17 test fixtures need new URLs.
- **Windows guidance (INSTALL-6).** README.md:18 is the only Windows mention, and every real-OBS check so far ran on macOS (checklist:1, docs/phase0-results.md:4). Windows validation is already roadmap task 4.4 (roadmap.md:177). When it runs, add a short "On Windows" note (Explorer may hide `.html`; the `file:///C:/...` address pastes unchanged) if anything turns out to differ.

### Dock UX
- **Mode toggle shows the current mode, not the action (DOCKUX-8).** The button reads "Manual" while in manual mode (live.ts:1238-1247), while Show/Hide beside it is labelled by action (live.ts:1068). Switching from Automatic to Manual stops a running count (counter.ts:323). Relabel it "Switch to Automatic" / "Switch to Manual". No test checks the label.

### Overlay
- **Oswald counters jitter on every tick (OVERLAY-1).** The bundled Oswald files have no tabular-figures feature, so the `tabular-nums` setting (src/shared/overlay-presentation.ts:233) does nothing for them. Oswald digits vary in width (the "1" is 385 units, the "0" is 550), which moves the layout by up to about 16 px at 96 px on every change and breaks PRD.md:137. Inter, the default, is fine. Apply a fix only when the font is Oswald: per-digit `inline-block` spans `1ch` wide ("0" is Oswald's widest digit), or a `min-width` in `ch`. Do not apply it to Inter, whose tabular digits are narrower than `1ch`. Add a Playwright check that "11" and "00" render at equal widths. Move this up if the church uses Oswald.
- **Setup preview cannot show on-air clipping (OVERLAY-2).** The preview only ever shrinks content to fit (setup.ts:466-529), while the overlay cuts off anything outside the canvas (renderer.ts:227-231). In Counter-in-front, a background label like "HALLELUJAH" (the PRD.md:199 example) runs past 1920 px from about a 121 px number size in Inter. Add a one-line "wider or taller than your canvas" note when the measured size exceeds the canvas, using the canvas size Diagnostics already reads, or 1920x1080 as a fallback. Do not draw a canvas-sized frame, because it would shrink the preview until it is unreadable.

### OBS integration
- **Hotkeys belong to a scene collection (OBSINT-7).** OBS stores the script list and its settings, including the key bindings, per scene collection (counter-hotkeys.lua:183-230; confirmed under `modules.scripts-tool` in the local scene JSON). Add a README sentence and a C8b checklist item to test one collection switch, and mention that the overlay source is per collection too.
- **Lua header overstates Phase 0 (OBSINT-5).** counter-hotkeys.lua:26-28 claims Phase 0 proved delivery for a source that is in no scene, but the probe used an input that was in a scene (phase0-results.md:33, 38; phase 3 plan:164). Reword it to "expected; verified at C3". Do not add `obs_source_remove`.

### Code structure
- **Typed dirty-field names (CODE-8).** `dirtyFields` is a `Set<string>` (setup.ts:244, 822, 1381-1407) with 31 lookups by string literal, so a typo in one would silently drop an operator's edit on Update. Declare a `SetupField` union that leaves out `mode` and includes `title`. It is about 15 minutes of type-only work.
- **Shared DOM helpers (CODE-4, part of CODE-3).** `el()` exists in four files (setup.ts:268, presets.ts:127, live.ts:193, diagnostics.ts:816), with four different `button()` signatures and repeated focus-restore code. `parsePort` is duplicated (live.ts:371, diagnostics.ts:834), and the default port 4455 appears in four places. Move them into `src/dock/views/dom.ts` when these files are next edited.
- **Add-overlay rendering in two views (CODE-3).** Duplicated rendering (diagnostics.ts:1177-1263, live.ts:531-658) over shared logic (diagnostics.ts:634). Low priority; keep the two failure messages separate (spec-locked at live.spec.ts:1023).
- **Setup logic as a testable module (CODE-1).** Validation and reconciliation live inside the `mountSetupView` closure (setup.ts:361, 601-1034), so only Playwright can reach them. The underlying rules already have unit tests, so do this after the walkthrough, and only if Setup rules start changing again.

### Dev workflow
- **Version strings disagree (DEVFLOW-1).** src/shared/version.ts:4 says `0.2.0-phase2`, package.json:5 says `0.1.0`, and the zip says 0.1.0. Diagnostics shows the first one (diagnostics.ts:1091, 1395), and the only test imports that same constant, so drift can never fail a test. Set version.ts to match package.json and add a unit test that checks they are equal. Name the zip from the same value. Do not use a Vite `define`, which would break the test setups.
- **Slow unit tests (DEVFLOW-5).** Two tests wait for real 3 s delays (controller.test.ts:1233, 1282), which account for about 6 s of the roughly 10 s suite. Shrink both numbers but keep their ratio. Leave the "nothing happens" waits in obsws-client.test.ts:85-89 as they are.
- **Dev script (DEVFLOW-4).** Plain `vite` fails at config load (vite.config.ts:26-31). A dock-only `dev` script helps with styling; dock and overlay would not talk across dev origins.
- **Node pin and CI (DEVFLOW-8).** There is no `.nvmrc`, no `engines` field and no CI. Add the Node pin now. CI is optional; if you add it, include a Windows job that runs typecheck, unit tests, build and the smoke and setup-page specs, but not the timing-sensitive UI suite.

## Considered and rejected

- **Remove Oswald 500, split fonts per page, or drop Inter 400 from the overlay (SIZE-1, SIZE-2, OVERLAY-5):** imported presets keep any font weight (setup.ts:245-259, tested at presets-setup.spec.ts:4609, 4689), so these faces are reachable, and a split would make the Setup preview and the overlay disagree.
- **Move the dock's inline CSS into a minified import (SIZE-3, CODE-6):** saves about 16 kB of a local file with no effect for the operator, and reverses a documented choice.
- **Build target and preload polyfill (SIZE-4):** a few kB, no change in behaviour.
- **Stop the duplicate localStorage bus writes (RUNTIME-3):** a deliberate fallback while delivery inside OBS's browser is unverified (checklist B1).
- **Change detection for the Diagnostics poll (RUNTIME-4):** runs only while that tab is open, and costs well under a millisecond.
- **Delayed event-log writes (RUNTIME-5):** the log is written rarely, and a delay would lose lines exactly when a crash happens.
- **Event-driven overlay name polling (RUNTIME-6):** a handful of cheap requests every 30 s, and the events fire on every hotkey anyway.
- **Skip identical overlay repaints (RUNTIME-8):** the browser already ignores identical writes, and the change risks a blank counter after Hide then Show.
- **Trim setup.html (INSTALL-4):** would break AC 32 (PRD.md:314) and its spec.
- **Rename Diagnostics rows (INSTALL-7):** the names match PRD.md:87 and OBS's own menu wording.
- **Separate packaging and checklist finding (INSTALL-8):** folded into item 3.
- **First-run banner change and a "Go to Setup" button (DOCKUX-5):** showing the banner and card together is intentional and tested (live.spec.ts:614), and the Setup tab is always visible.
- **Collapse Setup groups behind "Advanced" (DOCKUX-6):** reopens the layout the operator specified (PRD.md:244-253).
- **Enter applies Jump (DOCKUX-7):** contradicts the two-step Jump rule (PRD.md:144, AC 6).
- **Move the overlay-source service out of diagnostics.ts (CODE-2):** it is already exported and testable, and its shared state deliberately prevents duplicate source creation.
- **Sweep task references from comments (CODE-5):** most tagged comments carry real reasons, so this is a big careful edit for no runtime gain.
- **Split `boot()` (CODE-7):** rewrites a race-sensitive teardown order for a rare settings-save path.
- **Skip the rebuild before UI tests (DEVFLOW-3):** every UI spec loads the built pages, so the rebuild protects all of them.
- **Playwright tags, retries and more parallelism (DEVFLOW-6):** the worker cap is a documented fix for flaky runs, and retries would hide timing regressions.
- **Add typecheck to the test script (DEVFLOW-7):** the process already runs typecheck at every commit.
- **Dock and overlay may not share storage inside OBS (OBSINT-1):** OBS's source code shows custom docks and browser sources share one browser context, and checklist B1 already covers it.
- **Transport row reports availability, not delivery (OBSINT-2):** B1's test (counting with the password cleared) cannot pass falsely.
- **Reconnect loop when the password is missing (OBSINT-4):** obs-websocket answers with close code 4009, which is already treated as final.
- **Collapse the two overlay URL forms (OBSINT-6):** both forms are specified in PRD.md:277 and Ruling B.
- **Pre-load fonts before first paint (OVERLAY-3):** the fonts are inline and use `font-display: block`, and no gain was measured.
- **Hide the "Control panel closed" hint on air (OVERLAY-6):** required by AC 19 (PRD.md:301), and it is the only cue left in OBS once the dock is closed.

## Method

Eight reviewers each examined one area: bundle size, runtime efficiency, install flow, daily dock UX, code structure, tests and dev workflow, OBS integration, and overlay rendering. Together they produced 58 findings. Two adversarial verifiers then checked every finding. A fact-check lens tested the claims against the code and docs, and refuted 18. A worth-it lens asked whether the change would matter to this operator, and refuted 38. A finding was rejected when both lenses refuted it, or when one refuted it with high confidence. That left 29 confirmed and 29 rejected, and this report uses the verifiers' corrected severity and effort. The baseline was checked on 2026-09-25, before the review: typecheck clean, build succeeded, and 473 of 473 vitest tests passed.
